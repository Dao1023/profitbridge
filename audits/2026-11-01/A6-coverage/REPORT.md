# profitbridge 数据覆盖度与完整性审计（A6）

审计日期：2026-11-01（Asia/Shanghai）
范围：data/companies.json（92 家）、data/profit.json（3709 期）、data/segments.json（约 1126 期分部）、app.js:1447 界面 meta 行与 data/*.json 顶层 `source` 文案
方法：`node scripts/audit_coverage.mjs`（锚点聚类行走、停披阈值 365 天）跑基线 + 自写 `analyze.mjs` 逐公司重算「期数 / 起止 / 最新期距今天数 / frequency / 六字段缺失 / 分部滞后」，并对 app.js 与 data 文件做静态核对（mtime 与 updated 一致）
结论一句话：**利润面基本干净**（92 家仅 2 家共缺 3 期，无起止年份异常、无 frequency 与密度矛盾）；**缺口几乎全在分部**（BABA 断供 4.25 年、15 家港股分部止步 2024-12-31、9 家美股分部因单位核对被整段丢弃），且 UI 用单一全局「数据更新 2026-10-31 / 来源 SEC EDGAR XBRL」掩盖了 38 家非美主体的真实来源与分部真实截止日——属**「覆盖不均衡 + 标注不诚实」**，不是「数值算错」。

> 成品路径：`profitbridge/audits/2026-11-01/A6-coverage/`（草稿在 `tmp-audit/a6/`，内容一致）。

## 0. 口径说明（读数字前必看）

| 字段 | 定义 |
|---|---|
| `staleDays` | 2026-11-01 − 该公司最新期 `end`（天） |
| `missing[field]` | 该字段为 **null 的期数**（count，不是比例） |
| `segPeriods` | 分部期数 |
| `segComplete` | `segPeriods>0` 且 `|profit−seg 滞后| ≤ 200 天`。此「完整」= **分部及时可用**，**不是「4 段」**——分部段数天然因公司而异（2~8 段都有），<4 段不等于缺陷（如 NVDA 2026-04 起口径改 2 分部，已由 notes 说明） |
| `profitSegLagDays` | profit 最新期 − seg 最新期（正数=分部落后于利润） |

**关键方法论校正**：分部期与利润期的“日期缺口”多数是 **半年/年度披露节奏**（半导体、美股多只在 Q1/Q3 或年报披分部，间隔 182/365 天），**不是断供**；本报告只把 `|profit−seg 滞后| ≥ 300 天` 判为“陈旧”，不把天然半年度节奏计为缺陷。同理，跨币种/累计口径的「分部求和 ≠ 营收」多为单位与累计错配的伪差异（如 005930.KS seg=62454 / rev=73979187），**不据此判门店不完整**。

## 4. 与“逐值对错”无关的边界声明

- 本审计**不判定估值/价格正确性**（App 无价格类数据）；只判定“缺什么、旧到什么程度、标注是否诚实”。
- 分部求和 ≠ 营收的差异，对跨币种/累计公司是**口径伪差异**，未计入缺陷。
- 利润期覆盖已接近完整（3709 期仅缺 3 期），**利润面可视为健康**；本报告全部风险集中在**分部覆盖**与**UI 可信度标注**两块。
