# 已知口径差异（标注 / 复核记录）

本文档记录数据体检中发现的**数据源口径差异**与**已澄清的历史误报**。本项目遵循「如实呈现、不强行抹平」原则：口径差异是已知、有意保留的，**不通过改数去硬对齐**（硬改会重定义口径、破坏可溯源）；确属数据错误的（如 2026-11-20 的 NESN/MC 双重换算）则在数据管线修复，并在第五节留档。

不在本文档范围内（属真实业务或算法阈值噪音，勿混淆）：负毛利（MU / TSLA / PDD 等真实业务）、netInc 量级异常、相邻期量级跳变、rd+sga>gross 阈值告警等。

单位说明：数据以申报本位币 `-M`（百万）入库；前端默认按各期末 `fxToUsd` 折算 USD 展示。`opEq` = 营业利润 + 研发 + 销售管理 + 其他经营费用 − 毛利 ≈ 0（见 app.js:906）；`netEq` = 桑基净利润节点 vs 报表 `netInc`（折算后）的自检，阈值 0.005（见 app.js:907）。

> 最近复核：**2026-11-20**。证据数字、复算命令与逐条结论见 [audits/2026-11-20/README.md](../audits/2026-11-20/README.md)。

> **教训（为什么旧记录会错）**：用「同币种比值」验证分部合计并不可靠——若两侧都被同一条错误 fx 乘过，比值仍会 ≈1。当时 NESN 的 109,007 = 89,884.8 × 1.21274、MC 的 90,578 = 80,807.4 × 1.12091，两侧同乘一条 fx，恰好掩盖了双重换算。正确做法是拿「分部合计」对「利润表营收 × 该期 fx」做独立复算（本节的 annual ratio 就是这样得到的）。
